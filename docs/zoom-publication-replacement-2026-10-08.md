# Замена публикаций очереди в Zoom — 8 октября 2026

Обновления «Тем собрания» (очередь и доптемы) и «Вопросов спикеру» идут двумя независимыми потоками. Отправитель подтверждает все части нового состояния и только после этого удаляет предыдущие собственные сообщения. Обычные сообщения собрания, литература и сообщения участников не помечены для замены. История до включения функции не импортируется в журнал удаления.

Worker добавляет к сообщениям metadata publication: key, id, sessionDate, version, dayKey, partIndex, partCount. Опция completePublications в существующем outbox возвращает целые публикации; без неё прежний лимит выдачи сохраняется. Несколько быстрых изменений объединяются, состояния разных дней в пульте сохраняются независимо.

Журнал отправки находится в /app/profile/nafanya-publications.json (постоянный Docker volume, права 0600). Он атомарно сохраняет подтверждённые UUID и хеши текстов, неполные отправки и намерение удаления. После неоднозначной отправки бот сначала ищет точное собственное сообщение, не повторяет отправку вслепую. Намерение удаления включает идентификатор текущего входа и существовавшие системные отметки; подтверждение требует новой собственной отметки и исчезновения исходного UUID.

Zoom использует виртуализированный чат: отсутствие сообщения в текущем DOM не означает удаление. Для поиска сохранённых UUID выполняется ограниченная прокрутка истории. Кнопка меню — элемент zmu-drop-down, не обязательно HTML button. После удаления Zoom убирает исходный UUID и добавляет отдельную системную запись «Вы удалили сообщение». Эта запись допустима и не скрывается.

Подтверждены 71 автоматический тест отправителя, проверки пульта, очереди, литературы, Telegram-регрессий и браузерные проверки защиты UUID/автора/содержимого и системных отметок. В живой конференции Нафаня повторно вошёл, отправил оба типа публикаций; изменения и удаление тестовых строк дали новые состояния, прежние тексты заменились системными отметками. Дополнительно отправлена длинная публикация из двух частей: обе совпали по хешам с журналом, прежняя версия удалена; затем три длинные тестовые доптемы удалены штатными действиями. Проверены отсутствие тестовых строк в пульте и пустой outbox.

Важное ограничение: при полном повторном входе участника Zoom может не дать ему историю до этого входа. Бот сохраняет UUID, но не удаляет непроверяемые сообщения. Если прежняя публикация осталась у других участников, потребуется ручное удаление; пульт показывает отдельное предупреждение. При обычных изменениях в непрерывном входе замена проверена в реальном Zoom. Утверждение о бесшовном удалении через любой повторный вход не делается.

Восемь служебных записей раннего тестирования (до исправления распознавания отметок и после повторных входов) перенесены в отдельный резервный JSON на сервере. Проверены точные UUID и хеши; актуальные сообщения и другие записи не затронуты. Новые рабочие записи подтверждения сохраняются штатно.

Перед изменениями сохранены архив Git и приватная копия src/control-agent/Compose/.env на сервере. Обновление собрано поверх исходного рабочего Docker-образа с Playwright 1.63.0, без обновления браузера или учётных данных. Исправления в работающий процесс внесены без дополнительного выхода из конференции и затем сохранены в образе для следующих запусков. Временный диагностический порт Node привязан только к loopback контейнера и закрыт после проверки.
